# Strykd — Project Architecture & Build Brief

## What is Strykd?
Strykd (strykdapp.com) is an AI-powered accountability SaaS. Users describe their goals and time frame, the AI generates a personalized daily plan and visual theme, and deploys it to their own live subdomain (e.g. `edger.strykdapp.com`). The public page is shareable — visitors see the user's goals, streak, daily tasks, and a live signal wall. Users interact with their private dashboard to check off tasks, trigger AI replanning via a streaming endpoint, and manage their subscription.

## Stack
- **Backend:** FastAPI (Python)
- **Database:** PostgreSQL (Docker)
- **Cache:** Redis (Docker)
- **Frontend:** React (Vite)
- **Payments:** Stripe (monthly subscription)
- **AI:** Anthropic Claude API (claude-sonnet-4-20250514)
- **Deploy:** AWS EC2 + Nginx wildcard subdomain routing
- **SSL:** Let's Encrypt wildcard cert

## Core User Flow
1. User signs up at strykdapp.com → Stripe checkout → subscription active
2. Onboarding form: goals, time frame (days), aesthetic preference, identity slug
3. LLM generates: full daily plan, theme JSON, mission statement, Week chapter titles, Day 1 signal wall entry
4. Subdomain provisioned: `{slug}.strykdapp.com` goes live instantly
5. User logs into private dashboard daily → checks off tasks → interacts with LLM
6. LLM streaming replan: user requests change → FastAPI StreamingResponse → tokens stream to browser → user previews → confirms → DB write → Redis cache busted → public page updated
7. Signal wall: one AI-generated narrative entry per day, shown on public page as a live journal
8. Nightly cron (manual trigger week 1): generates next day tasks + daily headline + signal wall entry for all active users

## Database Schema

### users
- id (uuid, PK)
- email (string, unique)
- name (string)
- slug (string, unique) — maps to subdomain
- hashed_password (string)
- streak_days (int, default 0)
- last_checkin (date)
- subscription_active (bool, default false)
- created_at (timestamp)

### themes
- id (uuid, PK)
- user_id (uuid, FK → users)
- color_palette (string) — e.g. "dark-ember", "arctic-focus", "soft-earth"
- typography_variant (string) — e.g. "bold-condensed", "editorial", "minimal"
- layout_variant (string) — e.g. "cinematic", "dashboard", "journal"
- mission_statement (text) — AI-generated, 2-3 sentences
- daily_headline (text) — refreshed daily by cron
- chapter_titles (jsonb) — array of week chapter titles

### goals
- id (uuid, PK)
- user_id (uuid, FK → users)
- description (text)
- duration_days (int)
- start_date (date)
- end_date (date)
- status (string) — active, completed, paused

### daily_tasks
- id (uuid, PK)
- goal_id (uuid, FK → goals)
- task_date (date)
- content (text)
- voice_style (string) — direct, motivational, reflective
- completed (bool, default false)
- completed_at (timestamp, nullable)
- INDEX on (goal_id, task_date)

### signal_wall
- id (uuid, PK)
- user_id (uuid, FK → users)
- entry_date (date)
- ai_summary (text) — narrative journal entry generated by LLM
- tasks_completed (int)
- tasks_total (int)

### billing
- id (uuid, PK)
- user_id (uuid, FK → users)
- stripe_customer_id (string)
- stripe_subscription_id (string)
- status (string) — active, cancelled, past_due
- next_billing_date (timestamp)

## API Routes

### Auth
- POST /auth/register
- POST /auth/login
- POST /auth/logout

### Onboarding
- POST /onboarding — receives goals + preferences, triggers LLM generation, provisions subdomain record in DB

### Goals & Tasks
- GET /dashboard — returns user's goals, today's tasks, streak, theme
- PATCH /tasks/{task_id}/complete — marks task done, updates streak
- GET /public/{slug} — public page data (no auth), Redis cached TTL 10min

### AI
- POST /replan — StreamingResponse, receives change request, streams LLM tokens back, client shows preview
- POST /replan/confirm — writes confirmed replan to DB, busts Redis cache

### Stripe
- POST /billing/checkout — creates Stripe checkout session
- POST /billing/webhook — handles subscription events, updates billing table

### Cron (internal, auth-protected)
- POST /cron/nightly — triggers nightly content generation for all active users

## Streaming Replan Flow
1. User types change request in dashboard
2. 300ms debounce then POST /replan with {user_id, change_request, current_tasks}
3. FastAPI builds prompt with full user context from DB
4. Calls Anthropic API with stream=True
5. Yields each chunk as SSE event: `data: {token}\n\n`
6. Frontend EventSource reads stream, renders preview in real time
7. User taps "Apply" → POST /replan/confirm
8. DB updated, Redis cache invalidated for this slug

## Signal Wall
- Generated at signup (Day 1 entry)
- Generated nightly by cron for each active user
- Each entry: date, narrative summary (~3 sentences), tasks_completed/tasks_total
- Public page shows last 7 entries as scrollable feed
- Reads like a personal dispatch, not a log

## LLM Prompts (to be refined during build)

### Signup generation prompt
System: You are a world-class productivity coach and creative director. You generate personalized goal plans and visual identities.
User: Generate a complete plan for: {goals}, {duration_days} days, aesthetic preference: {aesthetic}. Return JSON with: daily_tasks (array by day), theme (color_palette, typography_variant, layout_variant), mission_statement, chapter_titles (one per week), day_1_signal_wall_entry.

### Replan streaming prompt
System: You are the user's personal AI accountability coach with full context of their goals and progress.
User: Current plan: {current_tasks}. Change request: {change_request}. Rewrite the affected tasks. Stream each task as you write it.

### Nightly cron prompt
System: You are generating daily content for an accountability platform.
User: User goals: {goals}. Today's completed tasks: {completed}. Generate: tomorrow's tasks (5 items), daily headline (1 sentence, cinematic), signal wall entry (3 sentences narrative).

## Day by Day Build Plan
- Day 1: Docker Compose up (PG + Redis), FastAPI scaffold, all models, auth routes, Stripe checkout + webhook, .env wired
- Day 2: Onboarding route, LLM signup generation, theme saved to DB, subdomain slug provisioned, basic public route returning data
- Day 3: React frontend — PublicPage renders with theme tokens, Checklist component, streaming replan endpoint + EventSource on frontend, Signal Wall component
- Day 4: AWS EC2 deploy, Nginx wildcard config, Let's Encrypt SSL, end to end test with real Stripe payment, soft launch

## Key Decisions
- No per-user deployment — one app serves all subdomains via slug lookup
- Redis caches public page data (TTL 10min) — busted on task complete or replan confirm
- LLM never writes to DB directly — FastAPI owns all writes
- Streaming uses SSE (Server-Sent Events) not WebSockets — simpler, sufficient
- Nightly cron is a manual POST /cron/nightly in week 1, automated in week 2
- Stripe webhook sets subscription_active flag — gating all LLM features behind payment
